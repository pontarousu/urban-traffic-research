# forward_traffic_ml

順方向シミュレーションを先に走らせ、その結果を観測断面交通量に近づけるために、発生率・分岐率・OD 傾向を補正する実験プロジェクトです。

既存の逆算的な交通シミュレーションとは独立した最小構成として作っています。最初の段階では機械学習を入れず、観測交通量を単純な統計量に変換して、通常の車両発生・移動・分岐を補正します。

## 目的

- 車を観測点から直接生成しない
- 観測断面交通量は、発生率・入口重み・分岐重みの補正に使う
- 東京全域ではなく、小領域・短時間で動作確認する
- 後から機械学習に置き換える場所を明確にする

## データについて

この公開版には、実交通量データ本体、観測地点コードと緯度経度の対応表、またはそれらを結合して生成した派生データを含めていません。

一部のスクリプトは、ローカル環境にある非公開の入力データを参照する前提で作られています。公開版では、コード構成、アルゴリズム、実験手順の記録を確認するためのものとして整理しています。

OSM由来データを使う場合は `© OpenStreetMap contributors` と https://www.openstreetmap.org/copyright を明記してください。

## 最小実行手順

1. 小領域データを作成します。

```bash
python3 src/preprocess.py
```

2. 順方向シミュレーションを実行します。

```bash
python3 src/simulate_forward.py
```

3. 観測値と比較します。

```bash
python3 src/compare_observed.py
```

## 現在の最小モデル

### 前処理

- 代表観測点を中心に、半径指定で OSM 道路網を小領域に切り出す
- 短時間の観測交通量を集計する
- 観測交通量から以下の補正量を作る
  - 地域全体の発生率
  - 領域入口候補の発生重み
  - 分岐先 Way の選択重み

### シミュレーション

- 車両は入口 Way から確率的に発生する
- 車両は Way の長さと速度制限に従って前進する
- 交差点では、接続 Way の重みに従って分岐する
- 観測点を通過した車両数を 5 分単位で集計する

### 比較

- 観測点・5 分枠ごとに `observed_count_5min` と `simulated_count_5min` を比較する
- MAE、RMSE、バイアス、相関係数を出す

## 注意

この段階のモデルは、現実の信号制御、渋滞波、車線変更、厳密な OD 推定をまだ扱いません。まずは「順方向に流して、観測値に近づける補正ループを作れるか」を確認するための土台です。

## 実験状況

現在は、道路DB版の順方向シミュレーション上で、交差点の分岐確率 `theta` を trace feedback または最小RLで更新する実験を行っています。

実験結果そのもののCSV/JSON、ビューア用の生成済みJSON、前処理済みデータは公開版に含めていません。主要な知見は `docs/` 以下のMarkdownに要約しています。
