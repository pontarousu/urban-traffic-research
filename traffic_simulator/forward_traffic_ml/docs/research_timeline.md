# 順方向交通シミュレーション研究の時系列

このメモは、公開版リポジトリを見た人が `forward_traffic_ml` の変更理由を追えるように、研究上の問題意識と実装の流れを整理したものです。

公開版には、実交通量データ、観測点コードと緯度経度の対応表、観測点と道路を対応付けた生成済みJSON、シミュレーション結果の詳細CSV/JSONは含めていません。ここに書く数値は、公開可能な範囲に丸めた集計指標です。

## 1. 順方向シミュレーションへの方針転換

当初は、観測断面交通量から車両を逆算的に配置する方式を検討していました。しかし、実際の都市交通を表すには、車両が通常の発生・移動・分岐を行い、その結果として観測点交通量が近づく構成の方が自然です。

そのため、`forward_traffic_ml` では以下を基本方針にしました。

```text
車両は観測点から直接生成しない。
観測断面交通量は、発生分布・分岐確率・評価関数の補正に使う。
```

## 2. 最小モデルと trace feedback

最初は、道路上を進む車両を1台ずつ扱い、交差点での分岐を `theta` という score と softmax で表しました。観測点を通過した車両の履歴を使い、その車両が過去に通った分岐へ誤差を戻す `trace feedback` を実装しました。

この段階で確認したことは、観測点周辺では学習が進む一方、観測点が疎な領域や車両が届きにくい領域では学習信号が弱いという点です。

## 3. 道路DB版への移行

OSMから直接得たノードは必ずしも交差点ではないため、分岐確率の学習単位として不安定でした。そこで、別プロジェクトで作成した道路DBの topology を使い、交差点・directed edge・turn relation を明示的に扱う構成へ移行しました。

この変更により、分岐確率は以下の単位で管理する方針になりました。

```text
(intersection node, incoming directed edge, outgoing directed edge)
```

## 4. 観測点マッチングとビューア

観測点と道路の対応付けには、位置ずれや上下線ペアの問題がありました。そのため、観測点・対応edge・誤差分布を地図上で確認するビューアを追加しました。

公開版ではビューア本体だけを含め、観測点緯度経度を含む `viewer/data/*.json` は含めていません。

## 5. 発生位置の見直し

観測点近くの上流から車両を出す方式だけでは、学習範囲が観測点周辺に偏りました。その後、メッシュ単位で発生源を分散させる `mesh_uniform` を導入し、道路網全体へ車両を広げる方向に変更しました。

この段階で、発生分布が学習可能範囲を強く左右することが分かりました。

## 6. パケット化による高速化

1台ずつ車両をシミュレーションすると計算量が大きくなり、iteration数を増やしにくい問題がありました。そこで、複数台を1つの代表車両として扱う packet simulation を導入しました。

この変更は、強化学習や多数iterationの比較を行うための計算基盤として重要でした。

## 7. 最小RL更新の導入

trace feedback は観測点に到達した車両履歴に基づく単純な更新でしたが、より一般的な policy 更新へ拡張するため、REINFORCE風の最小RL更新を実装しました。

主な構成は以下です。

```text
reward: 観測点・時間binごとの誤差率から計算
baseline: reward の基準値
advantage: reward - baseline
policy gradient: 分岐選択確率の log 勾配で theta を更新
```

## 8. baseline設計の比較

`global baseline` は全体量を押し上げる力が強い一方、観測点別の配分が崩れやすい傾向がありました。`observation baseline` は観測点別の暴走を抑えやすい一方、全体過小を押し上げる力が弱い傾向がありました。

そのため、両者を混ぜる `mixed baseline` と、自動的に混合比を調整する `mixed_auto` を試しました。

## 9. no_outgoing 構造ペナルティ

一部領域で観測点到達率が低く、行き止まり方向へ車両が流れやすい可能性がありました。そこで、次の outgoing が存在しない edge を選ぶ score に固定ペナルティを加える構造 prior を追加しました。

```text
score = theta + structural_penalty
structural_penalty = no_outgoing_penalty if 次の outgoing がない else 0
```

この変更により、観測点到達率や再現量の立ち上がりは改善しました。一方で、特定地域が過大になりやすい副作用も見えました。

## 10. 現在の課題

現在の主要課題は、全体の再現量を増やすだけでなく、地域ごとの過大・過小を抑えることです。

特に、観測点密度、道路網の連続性、発生分布の単純さが、地域別の偏りを生んでいる可能性があります。次の方向性として、道路周辺人口、昼間人口、建物用途、道路容量などを使った地域別 prior の導入を検討しています。

## 公開上の注意

このリポジトリでは、研究の再現に必要なコードと設計メモを公開し、再配布制限のあるデータは公開しない方針です。実験を実行するには、利用者自身が権利上問題のない入力データを用意し、各スクリプトの `--input` 系引数で指定する必要があります。
