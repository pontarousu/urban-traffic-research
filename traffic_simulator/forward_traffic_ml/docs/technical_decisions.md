# 技術的決定事項

このメモは、順方向交通シミュレーションの公開用設計ログです。
非公開の観測交通量、観測点位置、観測点コードと緯度経度の対応表、生成済み評価結果は含めません。

## 基本方針

- 車両は通常の発生、移動、分岐、消滅によって走らせる。
- 観測断面交通量は、車両を直接生成する命令ではなく、発生量や分岐確率を補正する情報として使う。
- 学習対象の中心は、交差点における incoming edge から outgoing edge への分岐確率とする。
- 分岐確率は直接保持せず、内部では `theta` というスコアを保持し、softmax で確率に変換する。

## 観測総量と発生量

観測総量は、対象領域内の観測点における5分交通量の合計として扱う。
これはユニーク車両数ではなく、延べ通過台数である。

初期実験では、5分ごとの発生量を観測総量に対する倍率で決める。
この倍率は固定パラメータとして扱い、最初の学習対象にはしない。

## 分岐確率の単位

分岐パラメータは node 単位ではなく、次の単位で持つ。

```text
(intersection_node, incoming_directed_edge, outgoing_directed_edge)
```

これにより、同じ交差点でも進入方向ごとに異なる分岐傾向を表現できる。

## 道路DBへの移行

初期実装では OSM way を直接使っていたが、曲線表現用 node や分岐を持たない node が多く、交差点分岐の学習対象として扱いにくかった。

そのため、現在は別途作成した道路DBスナップショットを使い、ネットワーク計算用データと描画用 geometry を分ける方針にしている。

公開版では道路DB出力そのものや、道路DBと観測点を結合した生成済みデータは含めない。

## 観測点マッチング

観測点の緯度経度と道路 geometry にはズレがあり得るため、単純な最近傍だけで確定しない。
近接観測点のペア、道路方向、進行方向、手動確認結果を踏まえて対応 edge を確認する。

公開版では、観測点の実位置や対応済み JSON は含めず、マッチング処理のコードと考え方のみを残す。

## trace feedback

trace feedback では、車両が観測点を通過したあと、その車両が過去に通った分岐履歴へ観測誤差を戻す。

```text
観測点で過小:
  その観測点へ到達した trace の分岐を強める。

観測点で過大:
  その観測点へ到達した trace の分岐を弱める。
```

更新対象は `theta` であり、更新後の分岐確率は softmax によって得る。

## 強化学習への移行

trace feedback は手作りの更新ルールである。
強化学習では、分岐選択を action、観測誤差から作る評価を reward として扱う。

最小構成ではニューラルネットワークを使わず、既存の `theta` table を policy parameter と見なす。
これにより、現行方式と同じシミュレータ条件で比較しながら、将来の NN policy へ接続しやすくする。

## 公開版で含めないもの

- 実観測地点の緯度経度
- 観測点コードと緯度経度の対応表
- 実交通量データ本体
- 実交通量と位置情報を結合した派生 JSON/CSV
- 生成済み道路DBスナップショット
- シミュレーション結果 JSON/CSV
- 観測点別の具体的な実測値や対応 edge を含む診断ログ
